## 一、课程定位

**一句话**：在 WorkBuddy 里用开源 Skills 和工具，以自媒体账号「阿夏的AI片场」为例，完成“找对标 → 账号诊断 → 视频拆解 → 爆款复刻 → 视频复刻 → 违规审核”，每一步都拿到能打开、能核对的文件。

| 项目 | 设定 |
| --- | --- |
| 学员 | 做 AI 视频的博主、小团队运营、想用 Agent 提效的创作者；不要求会编程 |
| 演示工具 | **WorkBuddy**（录屏全部用它，固定一个版本录制） |
| 工具来源 | JuneYaooo 的开源项目为主，加上 GitHub 热门项目（见第四节） |
| 平台 | 抖音、小红书为主，B 站、视频号在审核课覆盖 |
| 形式 | 每课 = Markdown 讲义 + 练习素材 + 可复制提示词 + 3–6 分钟带旁白录屏 + 核对清单 |
| 交付 | 静态网站（GitHub Pages），构建方式同 medical-teach |

### 沿用 medical-teach 的原则

1. **一个贯穿案例**：所有课围绕同一个虚构账号，前一课的产物是后一课的输入。
2. **每课一个“发现错误 → 纠正”**：Agent 给出结果后，学员核对一处数字、时间点或风险，并让 Agent 改正。这是每段录屏的重点镜头。
3. **数字可追溯**：倍数、播放量、时间戳都要能在数据表、原片或脚本输出里找到。
4. **不自动发布**：课程止步于“可发布的作品包”，发布由人完成。

## 二、贯穿案例：「阿夏的 AI 片场」

| 设定 | 内容 |
| --- | --- |
| 账号 | 虚构自媒体博主「阿夏」（AI 短片赛道），抖音 + 小红书，粉丝 5,800，起号 3 个月 |
| 内容 | AI 电影感短片、AI 产品广告、AI 动画小故事，偶尔发工具教程 |
| 问题 | 画面精致但播放不稳（200–3,000 波动）；不知道观众要看什么；有一条用了疑似明星脸的视频被限流 |
| 目标 | 找到可学的对标，做出一条“复刻爆款套路 + 自己能做出来”的视频，并且安全发布 |
| 对标 | 4 个虚构对标账号：AI 短剧号、AI 产品广告号、AI 教程号、一个“看着像但不是同赛道”的干扰项 |

### 练习包

`自媒体教程-练习包.zip` 解压后得到 `阿夏的AI片场/`：

```
阿夏的AI片场/
├── 开始前请读.txt
├── 资料/
│   ├── 账号档案.md                     # 定位、人设、目标、更新记录
│   ├── 自己账号-作品数据.csv            # 近 3 个月 40+ 条作品
│   ├── 候选对标-数据快照-第1周.csv / 第2周.csv
│   ├── 后台截图/*.png                   # 一条“没爆”作品的后台数据
│   ├── 爆款样片/*.mp4                   # 3 条自制：AI 短剧、AI 产品广告（H3 生成），AI 工具排行榜（代码视频）
│   ├── 爆款样片/*.srt、评论区.csv        # 样片的字幕和模拟评论
│   ├── 自己的作品/待发布.mp4、标题封面文案.md
│   └── 审核样例/                        # 故意埋了风险点的视频、封面和文案
├── 成果/                                # 学员自己的产物，初始为空
└── 参考结果/                             # 每课实际跑出的结果，可对照或跳课时复制
```

> 账号、数据、对标均为模拟。样片自制（AutoDL H3 生成 + HyperFrames 代码视频），不使用他人真实作品，避免课程本身侵权；人物全部是 AI 原创角色，不用真人肖像。课程不演示批量采集平台数据，练习全部用离线数据，保证每个人跑出的结果一致。

## 三、学习路线

```
00 总纲 · 01 入门（WorkBuddy 工作空间 + 安装 Skills）
   │
   ▼
① 找对标 ──▶ ② 账号诊断 ──▶ ③ 视频拆解(逆向) ──▶ ④ 爆款复刻 ──▶ ⑤ 视频复刻 ──▶ ⑥ 违规审核
 1-1 扫赛道筛对标 2-1 账号体检   3-1 下载并逐镜拆画面   4-1 换选题写我的版本  5-1 按方案还原画面   6-1 成片发布前审核
 1-2 对标爆款雷达 2-2 单条诊断   3-2 拆钩子、文案与评论  4-2 Hypit 克隆出变体  5-2 花字动效与返工   6-2 账号限流排查
   │
   ▼
07 结课：一条视频从找对标到可发布
```

| 模块 | 回答的问题 | 课程 |
| --- | --- | --- |
| 入门 | WorkBuddy 怎么设工作空间、装 Skill、核对结果 | 00、01 |
| ① 找对标 | 谁才是真对标？对标这周出了什么爆款？ | 1-1、1-2 |
| ② 账号诊断 | 我的号差在哪？这条为什么不爆？ | 2-1、2-2 |
| ③ 视频拆解（逆向） | 爆款的画面、剪辑、声音、钩子和文案是怎么做的？ | 3-1、3-2 |
| ④ 爆款复刻 | 保留爆款的套路，换成我的内容 | 4-1、4-2 |
| ⑤ 视频复刻 | 按拆解结果，把画面真正做出来 | 5-1、5-2 |
| ⑥ 违规审核 | 这条能不能发？账号为什么被限流？ | 6-1、6-2 |
| 结课 | 全流程串一遍 | 07 |

共 **15 节**。

两个“复刻”的区别：
- **爆款复刻**：学套路。结构、节奏、钩子不变，换成阿夏自己的主题和角色。
- **视频复刻**：学做法。按逐镜拆解的结果，把镜头、花字、剪辑还原出来。

### AI 视频生成：两条演示路线

课程里所有 AI 生成画面只用下面两条路线。H3 路线有两种接法：自己租 GPU（演示用），或直接调 API：

| 路线 | 用什么 | 成本 | 用在哪 |
| --- | --- | --- | --- |
| **H3 路线** | 开源 [MiniMax H3](https://huggingface.co/Comfy-Org/MiniMax-H3) 部署在 AutoDL 的 ComfyUI 上；用 [open-source-video-gen-skill](https://github.com/mini-yifan/open-source-video-gen-skill) 的 `minimax-h3`、`h3-prompt-writing`、`autodl-app-instance` 让 Agent 写提示词、自动开机、提交、下载、关机 | 只付 GPU 租金，项目实测 10 秒 1080p 约 ¥0.3（以 AutoDL 实际计费为准） | 样片制作、5-1 |
| **H3 路线 · API** | 不部署：Capsule Cinema 的 H3 渠道调 MiniMax 官方 API（`MINIMAX_API_KEY`，完整 Context-IR + 2K），或 RunningHub 上的 H3-Base 工作流（`RUNNINGHUB_API_KEY`） | 按次计费；历史参考价 5 秒 768p 约 ¥2.50、2K 重生成约 ¥0.30/输出秒，以平台当日价格为准 | 5-1 讲义里的“另一种接法”；录屏时没有 AutoDL 的兜底 |
| **代码视频路线** | [HyperFrames](https://github.com/heygen-com/hyperframes) 用 HTML 写画面；Hypit 的工作流也可以只用字幕、动效和代码画面，不调生成模型 | 不需要 GPU，几乎零成本 | 样片制作、4-2、5-2 |

- Hypit 需要接 H3 时，用 [comfyui-hypit-bridge](https://github.com/Ero-Cat/comfyui-hypit-bridge) 把 AutoDL 上的 ComfyUI 接成 Hypit 的生成服务（需 ≥24GB 显存实例），作为 4-2 讲义里的进阶选项，不录屏。
- Capsule Cinema 在 5-1、5-2 里管分镜、质量门、单镜头返工和配方；它的生成渠道改接 AutoDL H3，试跑时确认能否配置自定义 ComfyUI 端点，不行就由 `minimax-h3` 技能直接生成、Capsule Cinema 只做编排和 QA。
- 没有 GPU 预算的学员：全程走代码视频路线，所有课都能做完。

## 五、每课规划

统一字段：**目标 / 工具 / 输入 / 任务 / 产物 / 必须核对的一处 / 录屏重点**。时长是录屏目标时长。

### 00 总纲：课程导览（2–3 分钟）

- 目标：了解路线、案例和练习包，知道学习进度怎么看。
- 录屏重点：网站首页 → 下载练习包 → 解压看到三个文件夹 → 课程页复制提示词 → 标记已学完。

### 01 入门：WorkBuddy 工作空间与安装 Skills（5–6 分钟）

- 目标：把 `阿夏的AI片场` 设为工作空间；安装本课程用到的 Skills；理解“Agent 产出 → 打开文件 → 核对”的循环。
- 任务：让 Agent 读 `账号档案.md` 和作品数据，写一份 200 字账号现状摘要到 `成果/01/`。
- 必须核对：摘要里的粉丝数、平均播放与数据表是否一致（预计 Agent 会把均值和中位数混用）。
- 录屏重点：Skill 安装完整过程；文件落在哪；打开文件逐句对照。

---

### ① 找对标

#### 1-1 扫同赛道，筛出真对标（5 分钟）

- 工具：social-account-doctor。
- 输入：账号档案、`候选对标-数据快照-第1周.csv`。
- 任务：判断每个候选是不是真对标（赛道、内容形态、粉丝量级、更新节奏），选出 2–3 个并写清理由，每个对标标出“值得学的一点”。
- 产物：`成果/1-1/对标清单.md`。
- 必须核对：“看着像但不是同赛道”的干扰项被排除；理由能在数据表里找到。
- 录屏重点：对标理由逐条回查表格。
- 讲义里的提示（只文字说明，不演示）：练习包里的候选数据是现成的。真实账号想自己采集，可以用 [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 采小红书、抖音的公开数据，但要控制频率和数据量，采得太快太多容易被封号；只采公开数据、自用研究，遵守它的非商用许可和平台规则。

#### 1-2 对标爆款雷达：找到本周最值得拆的一条（4–5 分钟）

- 工具：benchmark-outlier-radar。
- 输入：1-1 对标清单、第 1 周和第 2 周的对标数据快照。
- 任务：按“近 15 条中位数”算基线，标出 5x/10x/25x 异常爆款，选出本周最值得拆的 1 条。
- 产物：雷达周报、`成果/1-2/本周待拆.md`。
- 必须核对：Agent 解读里的倍数与脚本输出一致（只解读、不改数）；一条互动率异常的数据被标“先核对”。
- 录屏重点：脚本数字 vs Agent 解读并排。

---

### ② 账号诊断

#### 2-1 账号体检：我在哪、差在哪（5 分钟）

- 工具：social-account-doctor。
- 输入：自己账号作品数据 + 1-2 对标清单。
- 任务：判断账号阶段；对比对标，找出差距最大的是调性、选题还是执行；从自己的 top/bottom 作品里总结规律；给出下一步 3 个动作。
- 产物：`成果/2-1/账号体检.md`。
- 必须核对：“你的爆款都是 XX 类型”这类结论，回到数据表数一遍是否成立。
- 录屏重点：结论回查数据。

#### 2-2 单条诊断：这条为什么不爆（4 分钟）

- 工具：social-account-doctor。
- 输入：`后台截图/`（完播率、点击率、平均观看时长）+ 该条封面和标题。
- 任务：逐项诊断封面、标题、开头 3 秒、发布时间、互动钩子，给出 3 个改法。
- 必须核对：Agent 读截图的数字是否读对；读错的那处当场纠正。
- 录屏重点：截图数字放大对照。

---

### ③ 视频拆解（逆向）

#### 3-1 下载对标爆款，逐镜拆画面（6 分钟）

- 工具：Douyin_TikTok_Download_API（下载）+ rea-video（逆向）。
- 输入：1-2 选出的那条爆款（练习时用 `爆款样片/` 中的 AI 短剧样片）。
- 任务：下载视频 → 逐镜拆画面（景别、运镜、风格）、花字（颜色、描边、出场方式）、剪辑节奏、配音与音乐；判断每镜是 AI 生成、代码动效还是录屏；反推每镜提示词；给出“合并成几次生成、用什么模型”的复刻方案。
- 产物：`成果/3-1/拆解报告.md`、字幕 SRT、复刻方案。
- 必须核对：随机抽 2 个镜头回到原片对照（花字出现时间、是否 AI 生成）；判断错的一镜让 Agent 修正。
- 录屏重点：拆解表和原片同屏对照。

#### 3-2 拆钩子、文案结构和评论区（4–5 分钟）

- 工具：social-account-doctor（拆爆款模式）。
- 输入：3-1 的字幕 SRT、标题封面、`评论区.csv`。
- 任务：钩子在第几秒、封面用哪种模板、结构是清单体还是故事体、转折和结尾怎么留人，评论区在聊什么（观众真正关心的点）。
- 产物：`成果/3-2/爆款拆解卡.md`。
- 必须核对：“钩子在第 X 秒”回到字幕时间轴确认；评论区结论回查 CSV 是否有足够条数支撑。
- 录屏重点：拆解卡与字幕、评论并排。

---

### ④ 爆款复刻（保留套路，换我的内容）

#### 4-1 换成我的选题，写出我的版本（5 分钟）

- 工具：social-account-doctor（仿写模式）。
- 输入：3-2 拆解卡、2-1 的账号体检建议、阿夏自己的一个新选题。
- 任务：保留爆款的结构和节奏，写出阿夏版本的脚本、分段画面描述、3 个标题和 3 个封面大字。
- 产物：`成果/4-1/脚本.md`、`标题封面.md`。
- 必须核对：没有照抄对标原句和原角色设定（只学结构）；标题夸大表述（“全网第一”“一键生成大片”）被改写。
- 录屏重点：对标结构与新脚本逐段对照。

#### 4-2 用 Hypit 克隆爆款工作流，批量出变体（6 分钟）

- 工具：Hypit（代码视频路线）。
- 输入：代码类爆款样片“AI 工具排行榜”+ 4-1 脚本。
- 任务：让 Hypit 把样片克隆成一套工作流（字幕、排行榜动效、配音、音乐都对齐到台词），把文案换成阿夏版本，再出 2 个变体（换榜单主题 / 换配色和角色贴图）。全程不调视频生成模型。
- 产物：`成果/4-2/` 工作流源文件、3 条成片。
- 必须核对：变体是否真的换掉了原片文案和素材（不能留下原作者的台词、Logo 或水印）；字幕与配音逐字对齐。
- 录屏重点：工作流源文件和预览并排；同一结构下 3 个变体对比。
- 讲义进阶：想克隆含 AI 人物镜头的爆款，用 comfyui-hypit-bridge 接 AutoDL H3（只写步骤，不录屏）。

---

### ⑤ 视频复刻（按拆解还原画面）

#### 5-1 按拆解方案还原 AI 镜头（6 分钟）

- 工具：rea-video 的复刻方案 → Capsule Cinema（分镜、QA）+ AutoDL H3（`h3-prompt-writing`、`minimax-h3`、`autodl-app-instance`）。
- 输入：3-1 复刻方案、4-1 脚本。
- 任务：按方案生成可审分镜 → 把每镜改写成 H3 提示词 → 先出 1 个校准镜头确认风格 → Agent 自动开机、整批提交、下载、关机 → 质量门检查 → 合成配音和字幕。
- 产物：`成果/5-1/` 成片 MP4、分镜表、H3 提示词、生成参数、GPU 用时与费用记录、QA 记录。
- 必须核对：成片和原片逐镜对照，景别、运镜、节奏是否还原；角色在不同镜头里是否一致；**任务结束后 AutoDL 实例确实已关机**（到控制台确认，避免空跑计费）。
- 录屏重点：校准镜头 → 整批生成（等待加速）→ 原片 / 复刻片左右对比 → AutoDL 控制台显示已关机。
- 备注：没有 GPU 预算的学员跳过生成，用参考结果里的成片继续 5-2。

#### 5-2 复刻花字和动效镜头，单镜返工后存成配方（6 分钟）

- 工具：HyperFrames + Capsule Cinema。
- 输入：3-1 里标为“代码动效”的镜头（花字、标题卡、UI 演示），5-1 成片。
- 任务：用 HyperFrames 写出这些动效镜头并渲染，替换进成片；对 5-1 里一个不合格的 AI 镜头单独返工；把整套流程保存成“AI 短剧”配方。
- 产物：HyperFrames 源文件、替换后的成片、配方文件。
- 必须核对：花字的颜色、出场时间与 3-1 拆解报告一致；返工只改了那一镜，其他镜头没被重新生成。
- 录屏重点：HTML 源码和渲染预览并排；返工前后对比。

---

### ⑥ 违规风险审核

#### 6-1 成片发布前审核（5–6 分钟）

- 工具：self-media-compliance-review。
- 输入：4-2 或 5-2 的成片 + 4-1 标题封面文案；目标平台：抖音、小红书。
- 任务：输出 Pass→Blocker 五级风险报告，每条带时间点、字幕行或封面文案证据；按建议修改后复审。
- 重点风险：AI 生成内容未标识、复刻内容与原作过于相似（原创争议）、疑似真人肖像、BGM 版权、导流话术、夸大宣传。
- 必须核对：一条 High 风险的证据定位是否准确（回到时间点看画面）；修改后复审降级。
- 录屏重点：证据定位 → 修改 → 复审。

#### 6-2 账号风险排查：为什么被限流（4–5 分钟）

- 工具：self-media-compliance-review（案例排查）。
- 输入：`审核样例/` 里那条被限流的“明星脸”视频和后台提示截图。
- 任务：列出可能原因（肖像、原创争议、搬运判定等）、排查顺序、整改动作和申诉材料清单。
- 必须核对：报告区分“平台规则”和“创作者经验”（经验只作线索，不当结论）。
- 录屏重点：原因 → 证据 → 整改清单。

---

### 07 结课：一条视频从找对标到可发布（6 分钟）

- 任务：用新的一周数据，依次走 1-2 → 3-1 → 4-1 → 4-2 或 5-2（用配方复刻）→ 6-1，展示每一步交接的文件。
- 产物：`作品包/`（成片、封面、标题、发布文案、审核报告）。
- 录屏重点：文件在各步骤之间流转。
