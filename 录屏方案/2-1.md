# 2-1 账号体检：用 AI 找出你的号差在哪 — 录制规格

## 基本信息

| 项目 | 内容 |
| --- | --- |
| 输出文件 | `自媒体教程/录屏/2-1-WorkBuddy实操.mp4`（及同名 .json、.vtt） |
| 目标时长 | 4 分 30 秒 – 5 分 30 秒 |
| 前置产物 | `$WS/成果/1-1/` 里的对标清单（1-1 实搜后勾选的 3 个真实账号） |
| 用到的素材 | `资料/账号档案.md`、`资料/自己账号-作品数据.csv`（演示账号的“后台导出”） |
| 外部条件 | 多模态 Key 已配；WorkBuddy 浏览器能读抖音页面，或 TikHub Key 已配（L2 需要） |
| 这一段要教会 | ① 技能先做环境自检，哪层跑不了第一句就说；② 漏斗 → 对标扫描 → 六维打分的顺序；③ 怎么用技能自己的规则核对报告：完整度、卡点、平均值陷阱、公式 vs 假设；④ AI 视频账号会多一节“AI 视频表达差距” |

## 演示参考值（核对用，不是标准答案）

- 演示账号 42 条作品，播放均值 1,152、中位数 655；粉丝 5,800。
- 分类型：电影感短片 18 条（中位数 480）、产品广告 10 条（520）、动画小故事 8 条（中位数 900、均值 1,340，被 ax-022 一条 4,100 拉高）、工具教程 6 条（中位数 3,100）。
- 后台导出只有播放、互动、完播率、涨粉，没有曝光和点击率：L1 漏斗应标为不完整（缺曝光、点击）。
- L2 的对标是 1-1 实搜到的真实账号，结果随录制时间变化，以实际为准。

## A. 录前重置

```sh
export WS=~/WorkBuddy录制/阿夏的AI片场
rm -rf "$WS/成果/2-1"
ls "$WS/成果/1-1/"   # 必须有 1-1 的对标清单；没有就先录 1-1
mkdir -p 录屏方案/_work/2-1/raw
```

`$WS/资料/` 是 `录屏方案/演示素材/` 的副本。在 WorkBuddy 里：关闭右侧预览区所有标签页；左侧任务列表清空或收起；确认统一模型；确认 social-account-doctor 已开启。Key 只在本机私有配置里，录制中任何时候都不能出现在画面上。

## B. 录制步骤

产物文件名以 Agent 实际生成为准，下文用的是示意名。

### S1 提交体检任务（原始片段 `2-1-S1.mp4`）

1. 开始录制。画面停在 WorkBuddy 首页 2 秒。
2. 点“新建任务”，确认输入框下方显示 `阿夏的AI片场`。
3. 点击输入框，粘贴（原样）：

```text
用 social-account-doctor 给我的抖音账号做一次完整诊断。我的主页：还没有公开链接，账号资料和后台导出的作品数据在资料文件夹里。对标用 1-1 我留下的那几个。先告诉我哪几层能跑、哪几层跑不了，再开始。最后给我 P0/P1/P2 的改进动作，分成“继续保持 / 从对标补齐 / 不要照抄”。结果放到 成果/2-1。
```

4. 停 3 秒。**标记 M1-1**。
5. 点发送。它回复环境自检（哪几层能跑）时，停 4 秒。**标记 M1-2**。
6. 等待生成完成（拉对标作品、看图的过程用加速）。出现报告文件卡片时，**标记 M1-3**。结束录制。

### S2 看报告（原始片段 `2-1-S2.mp4`）

1. 开始录制。点报告文件卡片，右侧预览打开。
2. 停在开头的完整度标注和 TL;DR，6 秒。**标记 M2-1**。
3. 滚到漏斗自检，停 5 秒。**标记 M2-2**。
4. 滚到对标扫描（爆款率、扑街率、选题分布），停 6 秒。**标记 M2-3**。
5. 滚到六维打分表，停 6 秒，差距 ≥2 的行要在画面里。**标记 M2-4**。
6. 滚到“AI 视频表达差距”一节，停 4 秒。**标记 M2-5**。
7. 滚到行动清单 P0/P1/P2，停 6 秒。**标记 M2-6**。
8. 结束录制。

### S3 演示核对（原始片段 `2-1-S3.mp4`）

1. 开始录制。在右侧预览区新标签页打开 `资料/自己账号-作品数据.csv`，停 3 秒。**标记 M3-1**。
2. 回到报告，找到报告里分类型的播放数据（或某条“XX 类内容表现最好 / 是另一类的几倍”的结论），停 5 秒。**标记 M3-2**。
3. 按“C. 分支”决定是否录 S4。结束录制。

### S4 追问依据（原始片段 `2-1-S4.mp4`）

1. 开始录制，回到同一任务。点击输入框，粘贴实际问题对应的追问（见 C）。停 3 秒，**标记 M4-1**。
2. 发送，等待完成。打开更新后的报告，停在被修改的段落 5 秒。**标记 M4-2**。
3. 结束录制。

## C. 分支（演示核对）

S3 时逐项检查报告，只纠正真实出现的问题，**不要为了配合脚本去诱导或伪造错误**：

| 检查 | 出现问题时的追问（把 `<>` 换成报告原文） |
| --- | --- |
| 用均值比内容类型（如“动画是电影感的近 3 倍”） | `你说我“<报告里的这条结论>”，依据是哪几条作品、哪些数字？动画小故事有一条 4,100 的爆款，按中位数比还成立吗？这是在我 2 条以上的作品里都验证过的，还是只是单条假设？` |
| 只出现 1 次的做法被写成“账号公式” | `你说我“<报告里的这条结论>”，依据是哪几条作品、哪些数字？这是在我 2 条以上的作品里都验证过的，还是只是单条假设？` |
| L1 缺曝光、点击却没标不完整 | `我的数据里没有曝光和点击率，漏斗前两层其实判断不了。请在报告开头标清完整度，并把依赖这两层的结论改成待验证。` |

- **主线**：出现上表任一问题 → 录 S4，剪辑用镜头 9–10。
- **分支 B**：报告完整度标注清楚、按中位数比较、公式和假设分开 → 不录 S4，剪辑用镜头 9B–10B。
- **L2 跑不了**（浏览器读不出且无 TikHub）：照实录 M1-2 的环境自检回复，报告应标“部分诊断，缺 Layer 2”；旁白镜头 3 改用“它第一句就说清楚了哪层跑不了”。在 report.md 写明。
