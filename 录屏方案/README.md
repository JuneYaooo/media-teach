# 录屏方案（给 Codex 的执行规格）

本文件夹是给执行者（Codex 或人）的**录制与剪辑规格**。照着做，就能录出 15 段带旁白和字幕的 WorkBuddy 教学录屏。

| 文件 | 用途 |
| --- | --- |
| `README.md`（本文件） | 所有课通用：交付物、环境、录制、剪辑、配音、分支、验收。**先完整读完。** |
| `实践手册.md` | 录屏、配音、双视图合成、拼接导出的实际命令和构图参数 |
| `样片制作.md` | 录课之前，先做好两条爆款样片（放进 `演示素材/爆款样片/`） |
| `演示素材/` | 演示账号“阿夏的AI片场”的全部素材，只给录屏用，学员看不到 |
| `00.md`、`01.md`、`1-1.md` … `6-2.md`、`07.md` | 每段录屏：点哪里、粘贴什么、等什么、怎么剪、旁白逐字稿 |

每课文件里，**代码块中的文字就是要粘贴的输入**：它和讲义里给学员的提示词相同，只是把 `<尖括号>` 换成了演示账号的值。规格里仍带 `<尖括号>` 的（比如 `<1-1 选定的对标>`），由你按当场实际结果填上，其余一个字都不要改。旁白逐字稿就是字幕和配音的原文。

课程定位（v0.7）：学员用**自己的账号**学会使用技能，讲义先讲技能原理（流程图），再给只写需求的提示词。录屏用演示账号“阿夏的AI片场”把这个过程完整演示一遍。找对标（1-1）和对标雷达（1-2、07）用的是**平台实搜到的真实账号**，结果会随录制时间变化；其他课用 `演示素材/` 里的虚构数据和自制样片。录制时发现规格和实际不一致，以实际为准，并写进执行报告。

## 一、总体顺序

1. **做样片**：按 `样片制作.md` 做出两条样片，放进 `录屏方案/演示素材/爆款样片/`，删掉 `样片待制作.txt`。
2. **确认外部条件**：WorkBuddy 有没有浏览器 / computer use 能力（决定 1-1、1-2、2-1 能否实搜平台）；看图模型 Key（`VIDEO_ANALYSIS_API_KEY`，硅基流动或 Gemini，见 01 讲义实操 1）是否可用；没有浏览器能力时是否有 TikHub Key。结果写进 `录屏方案/_work/兼容性.md`，缺什么先停下来问人。
3. **试跑兼容性**：按各课讲义“你要准备什么”里的安装提示词，在 WorkBuddy 里把全课用到的技能都装一遍，逐个确认能触发。01 只装 social-account-doctor；benchmark-outlier-radar（1-2）、rea-video（3-1）、Capsule Cinema（4-1）、open-source-video-gen-skill（5-1）、HyperFrames（5-2）、self-media-compliance-review（6-1）都在第一次用到的那课装。Hypit 是 4-1 讲义里“字幕卡片类的另一条路”，只在试跑时按讲义提示词装一遍确认能用，录屏不演示（理由见 `4-1.md` E 节后）。这几课的录屏开头有一段现场安装（S0），所以试跑装好后，各课 A 节会先在“已安装”里卸载本课技能再录，运行环境和本机配置保留。装不上的写进 `录屏方案/_work/兼容性.md`，交给人决定该课改用什么演示。**不要自行换工具。**
4. **不录屏完整试跑一遍**：在另一个工作空间副本里，按 01 → 07 的顺序把每课的实操 1 跑一遍（不录屏）。每课在 `录屏方案/_work/试跑.md` 记一行：是否跑通、技能是否按讲义“它是怎么工作的”那几步执行、该课规格“C. 分支”里的检查项哪几条没通过、出现了哪些明显问题、要花钱的步骤实际花了多少。写完**停下来交给人审**。人据此定稿每课的核对旁白，然后才开录。
5. **按顺序录课**：`01 → 1-1 → 1-2 → 2-1 → 2-2 → 3-1 → 3-2 → 4-1 → 4-2 → 5-1 → 5-2 → 6-1 → 6-2 → 07 → 00`。后面的课要用前面课的产物；00 是网站导览，最后录。
6. **保存演示结果**：每课录完，把 `$WS/成果/<课号>/` 复制到 `录屏方案/_work/<课号>/成果/`，供后面的课和讲义截图使用。不放进学员可见的网站目录。
7. **全部录完以后**：见第十节。

## 三、录制环境（每次开录前检查）

### 3.1 机器与软件

- macOS；WorkBuddy 固定一个版本，15 段统一，版本号写进每份 report.md。
- 统一模型：在输入框右下角的模型菜单里选定一个，15 段不换。
- ffmpeg、ffprobe、Python 3.10+、Python 3.12（Capsule Cinema 需要）、Node.js 22+（HyperFrames 需要；Hypit 试跑也要）。先用 `command -v` 确认路径。
- 配音：MiniMax `speech-2.8-turbo`，音色 `male-qn-jingying`，语速 1.08；按 capsule-cinema（cheap-claude-video）现有配置调用，不回退到其他声音。
- 字体：PingFang（本机路径见 `实践手册.md`）。

### 3.2 录制专用工作区

**不要在仓库里录。** 用演示素材复制出来的干净工作区：


### 3.4 WorkBuddy 界面状态

- 窗口 **1440×900**，放在主屏幕左上角。其余窗口最小化。
- 左侧任务列表只留本课任务；做不到就收起侧栏。
- 右侧预览区开录前关闭所有标签页。
- 每个新任务都确认输入框下方显示工作空间 `阿夏的AI片场`。

### 3.4.1 两类文字分清楚

每课规格里有两类文字，不要混用：

| 类别 | 长什么样 | 给谁 | 怎么用 |
| --- | --- | --- | --- |
| 提示词 | 「粘贴（原样）」后面的 ```` ```text ```` 代码块 | WorkBuddy 里的 AI（讲义提示词 + 演示账号的值） | 只填规格里剩下的 `<尖括号>`，其余一字不改粘进输入框。不加“当前工作空间是……”“我用的是 WorkBuddy”这类开场白，也不加任何录屏相关的话 |
| 操作说明 | 代码块以外的步骤、检查项、分支、剪辑表 | Codex | 自己照做：选工作空间、确认版本、整理窗口、判断分支。这些都在界面上完成，不靠告诉 AI |

工作空间、软件版本这类信息，AI 从界面和工作空间里就能拿到，不需要写进提示词。

提示词按学员的口吻写，只说需求：用哪个技能、想要什么结果、哪些要求是核对和安全的关键（数字不能编、Key 不进对话、先出一镜再批量、用完关机等）。具体读哪个文件、存成什么文件名、用什么命令参数，交给 Agent 和技能自己处理；最多说一句“放到 成果/<课号>”。因此每课产物的**文件名以 Agent 实际生成为准**，规格里写的文件名只是示意，核对时看内容，不看名字。

### 3.5 系统状态与隐私

- 勿扰模式；提前授予 WorkBuddy 文件夹访问权限，避免录制中弹窗。
- 隐藏桌面图标；菜单栏不显示个人信息。
- **账号、Token、API Key、AutoDL 控制台的账号信息一律不得出现在画面上。** 需要输入时先暂停录制；画面里漏出时整段重录，不能靠打码补救。
- 5-1 等用到 AutoDL 的课：录完立刻到 AutoDL 控制台确认实例已关机，在 report.md 写明 GPU 用时和费用。
- 4-1、4-2、07 用 Capsule Cinema 出片：配音渠道的 Key 录前在镜头外配好，不上屏；Agent 调用任何计费渠道前要先报渠道和费用，确认后才做（没报就停下来先问）；卡片和字幕走本地渲染，不调用图片、视频生成。实际花费写进 report.md。
- **真实账号**（1-1、1-2、2-1、07 实搜到的）：画面里只出现账号名和公开数据，不给头像和个人信息特写；旁白只讲技能怎么判断，不评价具体账号好坏；不点开私信、不关注、不点赞。

## 四、录制方法

命令见 `实践手册.md` 第 2 节。要点：

- 每课文件“B. 录制步骤”里的 S0（安装技能，部分课有）、S1、S2…… 每一步录成一个原始片段 `录屏方案/_work/<课号>/raw/<课号>-S<n>.mp4`。
- 不录系统声音。
- 遇到 **标记**（如 `M1-2`）就记下秒数，写入 `_work/<课号>/marks.json`，误差 0.5 秒以内。
- **输入一律粘贴**：`pbcopy` 写入剪贴板 → 点输入框 → `Cmd+V` → 停 3 秒 → 发送。
- **等待完成**的判断：回复结束、输入框按钮从停止状态变回发送箭头。单次等待超过 15 分钟视为失败（5-1 的 GPU 生成除外，以该课规格为准）。
- 失败或报错：新建任务，重新粘贴，重录这一步，记进 report.md。
- 鼠标慢移；滚动每次最多半屏，到位后停 3 秒。
- 画面出现弹窗、无关会话、其他课的标签页 → 这一步重录。

## 五、剪辑方法

### 5.1 配音

1. 旁白逐字稿按第六节替换读音，得到朗读稿（只用于配音，字幕用原文）。
2. 用 capsule-cinema 的 MiniMax TTS 生成（命令见 `实践手册.md` 第 3.1 节），完整听一遍，读错就改朗读稿重生成该镜头。
3. 镜头时长 = max(配音时长, 剪辑表“最短时长”)。
4. 画面短于配音：最后一帧定格补齐。画面长于配音：等待类画面加速（最高 16 倍），正常操作不加速。

### 5.2 画面处理词汇表

剪辑表“画面处理”一栏只用下面这些说法：

| 写法 | 做法 |
| --- | --- |
| **双视图（默认）** | 1920×1080 暖白画布；左侧完整应用界面，右侧同步放大当前操作区域；顶部写章节和动作，字幕在底部留白。尺寸和模板见 `实践手册.md` 第 4 节 |
| **全窗口** | 显示完整应用窗口 |
| **放大：左栏** / **放大：右栏** | 双视图右侧细节窗展示对话区或预览区 |
| **放大：输入框** | 细节窗展示输入框 |
| **放大：「关键词」** | 用 OCR 或手动坐标定位，在细节窗放大；关键词所在行不得截断 |
| **红框：「关键词」** | 外扩 8px，线宽 6px，`#E5484D`（错误） |
| **绿框：「关键词」** | 同上，`#30A46C`（正确 / 改后） |
| **黄框：「关键词」** | 同上，`#F5A524`（注意） |
| **并排：A ｜ B** | 两个画面各约 940×1000，左右排列，间隔 20px，上方各加小标题 |
| **加速 ×N** | `setpts=PTS/N`，右上角角标“实际等待 X 分 Y 秒 · 已加速” |
| **标题卡** | 暖白 `#F7F6F0` 背景，深墨色标题，青绿色点缀，约 2–4 秒 |
| **字卡** | 同样式，2–3 行要点，每行前加 ①②③ |
| **角标：文字** | 右上角圆角色块 + 白字，36px |

本课程额外用到两种画面（视频类课程需要）：

| 写法 | 做法 |
| --- | --- |
| **竖屏视频** | 1080×1920 的样片或成片，等比缩放到高 900，居中放在暖白画布上；左右可放说明文字 |
| **原片 ｜ 复刻** | 两条竖屏视频同步播放，左右并排，各自上方标“原片”“复刻” |

**OCR 定位**：用 macOS Vision 框架写小脚本，输入一帧截图和关键词，输出外框坐标。找不到时改用人工坐标，记进 report.md。

### 5.3 字幕

- 旁白逐字稿就是字幕原文。超过 22 字按标点切行（每条最多 2 行，每行最多 22 字），时间按字数比例分配。
- 硬字幕：底部居中，深墨色 PingFang 常规字重约 38px，浅色描边，不加黑底条，距底边约 54px。
- 同时输出同内容 `.vtt`。

### 5.4 合成与导出

- 镜头之间直接切，章节之间可加 0.3 秒淡入淡出。不加背景音乐。
- 样片和成片自带声音的镜头：原声压到 -18dB 垫在旁白下；没有旁白的展示镜头（如“原片 ｜ 复刻”）原声恢复正常音量，最长 8 秒。
- 导出命令见 `实践手册.md` 第 5 节。单个文件 60MB 以内，超过就把 crf 调到 26。

## 八、Agent 输出和预期不一样时

每课的“演示核对”环节，是按该课规格“C. 分支”里的检查项，在录屏里演示确认结果。讲义已经没有“怎么核对结果”一节，旁白和字幕不要说“讲义里的核对清单”之类的话。每课“C. 分支”写了判断方法：

- **核对发现了问题** → 主线：用自然的话告诉它哪里不对、为什么（规格给了示例说法），录下改后结果。
- **核对都通过了** → 分支 B：不发纠正指令，用分支 B 旁白（“这次它都做对了，你自己做时重点看这里……”），放大展示通过的地方。**不要为了配合脚本去诱导或伪造错误。**
- **技能没按原理图的步骤执行**（比如没实搜就给结论、没看图就判断画面）→ 照实录下，写进 report.md，交给人决定是否重录。

数字类结果（倍数、条数、秒数）和规格不一致时，**以实际生成的为准**，改旁白和字幕，并在 report.md 列出差异。
