# 01 入门：工作空间与 Skills — 录制规格

## 基本信息

| 项目 | 内容 |
| --- | --- |
| 输出文件 | `自媒体教程/录屏/01-WorkBuddy实操.mp4`（及同名 .json、.vtt） |
| 目标时长 | 4 分 00 秒 – 5 分 30 秒（整体规划写 5–6 分钟；安装等待已加速，以完整讲清为准） |
| 前置产物 | 无 |
| 用到的素材 | `资料/账号档案.md`、`资料/自己账号-作品数据.csv`；benchmark-outlier-radar 的 GitHub ZIP；social-account-doctor 的安装说明链接 |
| 这一段要教会 | ① 把 `阿夏的AI片场` 选为工作空间；② 检查 Python / Node / ffmpeg / git；③ 两种装技能的方法：界面上传 ZIP、让 WorkBuddy 按安装说明自己装；④ Key 自己填，不进对话；⑤ 第一个任务：账号摘要，抓出“粉丝数”和“均值当常态”两个错；⑥ 到文件夹确认文件真的存在 |

## 预期结果

- 环境检查表：Python、Node.js、ffmpeg、git 四行，每行有实际版本号。
- benchmark-outlier-radar 通过“上传技能”装好，“已安装”里开关为开。
- social-account-doctor 由 WorkBuddy 按 `install.md` 装好；Agent 先说明安装目录，再安装；需要 Key 时停下来让人填。
- `成果/01/账号现状摘要.md` 的标准答案：抖音粉丝 **5,800**（不是累计新增关注 6,240）；作品 **42** 条；播放中位数 **655**，均值 **1,152**（被爆款拉高，只作补充）；表现最好的是工具教程类，最差的是电影感短片。

## A. 录前重置

```sh
export WS=~/WorkBuddy录制/阿夏的AI片场
rm -rf "$WS/成果/01"
mkdir -p 录屏方案/_work/01/raw
mkdir -p ~/WorkBuddy录制/技能包
# 提前下载 benchmark-outlier-radar 的 ZIP（镜头外完成，画面里只演示网页上的下载按钮）
curl -L -o ~/WorkBuddy录制/技能包/benchmark-outlier-radar-main.zip \
  https://github.com/JuneYaooo/benchmark-outlier-radar/archive/refs/heads/main.zip
```

在 WorkBuddy 里：

1. “专家·技能·连接器”→“技能”→“已安装”：如果已有 `benchmark-outlier-radar`、`social-account-doctor`，先卸载（按钮名记进 report.md）。同时删除 social-account-doctor 上次装到的技能目录（路径以上次 Agent 说明的为准），否则 Agent 会提示“已存在”。
2. 其余技能（rea-video、self-media-compliance-review 等）本段不演示，录前不必处理。
3. 关闭右侧预览区所有标签页；左侧任务列表清空或收起。
4. 准备好 social-account-doctor 需要的多模态模型 Key，存在本机安全位置；**录制中不得出现在画面上**。

浏览器（S3 用）：无痕窗口，1440×900，打开 `https://github.com/JuneYaooo/benchmark-outlier-radar`，先最小化。

## B. 录制步骤

### S1 选择工作空间（原始片段 `01-S1.mp4`）

1. 开始录制。画面停在 WorkBuddy 首页 2 秒。
2. 点左上角“新建任务”。鼠标慢慢移到输入框下方的工作空间按钮，点击。
3. 菜单里点“打开本地文件夹”。
4. 文件选择窗口里按 `Cmd+Shift+G`，粘贴下面的路径并回车，再点“打开”：

```text
~/WorkBuddy录制/阿夏的AI片场
```

5. 输入框下方显示 `阿夏的AI片场`，鼠标停在文件夹名旁 3 秒。**标记 M1-1**。
6. 结束录制。

### S2 检查电脑环境（原始片段 `01-S2.mp4`）

1. 开始录制。在同一任务里点击输入框，粘贴（原样）：

```text
请检查这台电脑有没有装好：Python 3.10 以上、Node.js 22 以上、ffmpeg、git。逐个运行查看版本的命令，把结果列成一张表（工具、要求版本、实际版本、是否满足）。缺的告诉我在 macOS 上怎么装，先不要自己安装。
```

2. 停 3 秒。**标记 M2-1**。
3. 发送。WorkBuddy 请求执行命令时点“允许”。等待完成，回复里出现版本表时 **标记 M2-2**。
4. 停 3 秒，结束录制。

### S3 网页下载技能包（原始片段 `01-S3.mp4`）

1. 切到浏览器（benchmark-outlier-radar 仓库页）。开始录制，停 2 秒。
2. 点绿色“Code”按钮，菜单展开，鼠标停在“Download ZIP”上 3 秒。**标记 M3-1**。（不点击；ZIP 已在录前下载好。）
3. 按 Esc 收起菜单，向下滚动到 README 的“如何安装与使用”一段，停 3 秒。**标记 M3-2**。
4. 结束录制。

### S4 上传技能（原始片段 `01-S4.mp4`）

1. 切回 WorkBuddy。开始录制。
2. 左侧栏点“专家·技能·连接器”，再点顶部“技能”。停 2 秒。
3. 点右上角“添加技能”→“上传技能”。
4. 文件选择窗口按 `Cmd+Shift+G`，粘贴下面的路径并回车，点“打开”：

```text
~/WorkBuddy录制/技能包/benchmark-outlier-radar-main.zip
```

5. 等检测结果出现，停 4 秒。**标记 M4-1**。
6. 点安装 / 确认。
7. 点右上角“已安装”，找到 `benchmark-outlier-radar`，确认开关开启，鼠标停在开关旁 3 秒。**标记 M4-2**。
8. 结束录制。

> 如果上传后提示找不到 `SKILL.md`（GitHub ZIP 多了一层 `benchmark-outlier-radar-main/` 文件夹），停止录制：在镜头外解压后把里面的文件夹重新压缩成 `benchmark-outlier-radar.zip`（根目录直接是 `SKILL.md`），用新文件重录 S4，并在 report.md 和讲义第 4 节补一句说明。

### S5 让 WorkBuddy 安装技能（原始片段 `01-S5.mp4`）

1. 开始录制。点“新建任务”，确认工作空间为 `阿夏的AI片场`。
2. 点击输入框，粘贴（原样）：

```text
请帮我安装 social-account-doctor 技能，安装说明在：
https://raw.githubusercontent.com/JuneYaooo/social-account-doctor/main/docs/install.md
请先告诉我你打算把技能装到哪个目录、为什么装在那里能被识别，我确认后再装。需要填 API Key 时停下来，告诉我写到哪个文件的哪一行，我自己填，不要在对话里显示任何 Key。装完告诉我是否需要重启。
```

3. 停 3 秒。**标记 M5-1**。
4. 发送，等它回复安装目录和理由。回复出现目录路径时 **标记 M5-2**，停 3 秒。
5. 点击输入框，粘贴（原样）并发送：

```text
确认，就装到这个目录。
```

6. 等待安装（克隆仓库、装依赖时间较长，不动鼠标）。WorkBuddy 请求执行命令时点“允许”。出现“请填写 Key / 写到 .env”一类提示时 **标记 M5-3**，停 3 秒。
7. **暂停录制**。在镜头外按 Agent 说的位置填好 Key，保存。确认屏幕上没有 Key 残留后继续。
8. 恢复录制（新片段 `01-S5b.mp4`）。在输入框粘贴并发送：

```text
Key 已经填好了，请继续安装并检查是否装好。
```

9. 等待完成，出现“安装完成”一类说明时 **标记 M5-4**。
10. 如提示需要重启：退出并重新打开 WorkBuddy（镜头外完成）。
11. 进入“专家·技能·连接器”→“技能”→“已安装”，找到 `social-account-doctor`，鼠标停在开关旁 3 秒。**标记 M5-5**。看不到时按讲义第 4 节“以试跑为准”的方法处理，并记入 report.md。
12. 结束录制。

> 第 8 步的“Key 已经填好了……”是现场回复，不在讲义里；如果 Agent 填完 Key 后自己继续，就不用发送。

### S6 第一个任务：账号摘要（原始片段 `01-S6.mp4`）

1. 开始录制。点“新建任务”，确认工作空间为 `阿夏的AI片场`。
2. 点击输入框，粘贴（原样）：

```text
请读取 资料/账号档案.md 和 资料/自己账号-作品数据.csv，写一份 200 字左右的账号现状摘要：粉丝数、作品数、更新频率、一般一条作品有多少播放、表现最好和最差的内容类型。需要计算的数字请写脚本算，不要估算；每个数字注明来自哪个文件。保存到 成果/01/账号现状摘要.md。
```

3. 停 3 秒。**标记 M6-1**。
4. 发送，等待完成。回复里出现运行脚本的提示时 **标记 M6-2**；出现 `账号现状摘要.md` 文件卡片时 **标记 M6-3**。
5. 停 2 秒，结束录制。

### S7 看摘要（原始片段 `01-S7.mp4`）

1. 开始录制。点击 `账号现状摘要.md` 文件卡片，右侧预览打开。
2. 停在写粉丝数的那一句 4 秒。**标记 M7-1**。
3. 停在写“一般一条播放”的那一句 4 秒。**标记 M7-2**。
4. 结束录制。

### S8 回资料看原数（原始片段 `01-S8.mp4`）

1. 在 Finder 打开 `$WS/资料/账号档案.md`（用“文本编辑”或任一 Markdown 预览，窗口 1440×900）。开始录制。
2. 停在“抖音粉丝 5,800”“累计新增关注 6,240”“累计取关 440”那几行 4 秒。**标记 M8-1**。
3. 关闭窗口，结束录制。

**此时按“C. 分支”判断是否录 S9。**

### S9 纠正两处数字（仅主线，原始片段 `01-S9.mp4`）

1. 开始录制，回到 S6 的任务。点击输入框，粘贴（原样）：

```text
请核对摘要里的两处数字：
1. 账号档案里抖音粉丝是 5,800，这是净值；6,240 是累计新增关注，没有扣掉 440 个取关。摘要里的粉丝数应写 5,800。
2. 42 条作品的播放均值约 1,152，但被几条爆款拉高了；中位数是 655。“一般一条有多少播放”应该用中位数，均值可以作为补充，并说明为什么两者差这么多。
请修改 成果/01/账号现状摘要.md，并在文末列出每个数字的来源文件和算法。
```

2. 停 3 秒。**标记 M9-1**。
3. 发送，等待完成。
4. 打开更新后的 `账号现状摘要.md`，停在粉丝数和播放两句 5 秒。**标记 M9-2**。
5. 滚到文末“来源”部分，停 3 秒。**标记 M9-3**。
6. 结束录制。

### S10 确认文件存在（原始片段 `01-S10.mp4`）

1. 开始录制。切到 Finder，打开 `$WS/成果/01/`，选中 `账号现状摘要.md`，停 3 秒。**标记 M10-1**。
2. 结束录制。

## C. 分支

S7 结束后检查摘要：

```sh
F="$WS/成果/01/账号现状摘要.md"
grep -n -E "6,?240" "$F"          # 粉丝数是否写成 6240
grep -n -E "5,?800" "$F"
grep -n -E "(^|[^0-9])655([^0-9]|$)" "$F"   # 是否提到中位数
grep -n -E "1,?152|一千" "$F"
```

- **主线**（录 S9）：满足任一条——粉丝数写成 6,240（或把 6,240 当粉丝数）；没写 5,800；没有出现中位数 655，而用均值 1,152 或“一千多”描述“一般一条播放”。
  - 只错了一处：仍原样发送 S9 的文字，旁白只讲错的那处（镜头 14 的旁白二选一，见剪辑表备注）。
- **分支 B**（跳过 S9）：粉丝写 5,800，且“一般一条”用的是中位数 655。剪辑表镜头 14–16 换成分支 B 镜头。
- 出现别的明显错误（例如作品数不是 42）：照实录，写进 report.md，录完由人决定是否补纠正。
