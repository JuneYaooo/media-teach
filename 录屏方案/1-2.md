# 1-2 对标爆款雷达：找到本周最值得拆的一条 — 录制规格

## 基本信息

| 项目 | 内容 |
| --- | --- |
| 输出文件 | `自媒体教程/录屏/1-2-WorkBuddy实操.mp4`（及同名 .json、.vtt） |
| 目标时长 | 2 分 45 秒 – 3 分 45 秒（整体规划写 4–5 分钟；按本段旁白量实际约 3 分钟，以完整讲清为准） |
| 前置产物 | `$WS/成果/1-1/对标清单.md`（缺失时 `cp -R "$WS/参考结果/1-1" "$WS/成果/1-1"`） |
| 用到的素材 | `资料/对标快照-2026-10-31/镜头造梦师.csv`、`一帧一世界.csv`、`AI工具铺子.csv`；技能 benchmark-outlier-radar |
| 这一段要教会 | ① 用“倍数”而不是绝对播放判断爆款；② 倍数 = 单条播放 ÷ 近 15 条中位数；③ 固定基准日；④ 数字由脚本算，Agent 只解读、不改数；⑤ 互动率异常（⚠️）的先核对，不能当爆款学；⑥ 一条学内容套路、一条学画面做法 |

## A. 录前重置

```sh
export WS=~/WorkBuddy录制/阿夏的AI片场
rm -rf "$WS/成果/1-2"
[ -f "$WS/成果/1-1/对标清单.md" ] || cp -R "$WS/参考结果/1-1" "$WS/成果/1-1"
mkdir -p 录屏方案/_work/1-2/raw
```

在 WorkBuddy 里：关闭右侧预览区所有标签页；左侧任务列表只留本课或收起；确认 `benchmark-outlier-radar` 在“已安装”中开启；确认统一模型。

## B. 录制步骤

### S1 提交雷达任务（原始片段 `1-2-S1.mp4`）

1. 开始录制。画面停在 WorkBuddy 首页 2 秒。
2. 点“新建任务”，确认输入框下方显示 `阿夏的AI片场`。
3. 点击输入框，粘贴（原样）：

```text
当前工作空间：阿夏的AI片场。
请使用 benchmark-outlier-radar 技能，对 资料/对标快照-2026-10-31/ 里的 3 个对标账号文件跑对标雷达，基准日 --as-of 2026-10-31，周报保存到 成果/1-2/雷达周报.md，同时输出 成果/1-2/雷达.json。
然后解读异常爆款：每条只引用周报里的倍数和数字，不要改数；可能的原因（选题、标题、发布时间）写成假设。带 ⚠️ 的条目先列为“待核对”。
最后结合 成果/1-1/对标清单.md 和 资料/账号档案.md，选出本周最值得拆的条目，写清选它的理由，并注明它要学的是“内容套路”还是“画面做法”。保存到 成果/1-2/本周待拆.md。
```

4. 停 3 秒。**标记 M1-1**。
5. 发送。回复里出现运行 `build_radar.py`（含 `--as-of 2026-10-31`）的命令时 **标记 M1-2**，WorkBuddy 请求执行命令时点“允许”。
6. 等待完成。出现 `雷达周报.md`、`本周待拆.md` 文件卡片时 **标记 M1-3**。
7. 停 2 秒，结束录制。

### S2 看雷达周报（原始片段 `1-2-S2.mp4`）

1. 开始录制。点击 `雷达周报.md` 文件卡片，右侧预览打开。
2. 滚到各账号基线（中位数）部分，停 4 秒。**标记 M2-1**。
3. 滚到异常爆款榜，三条都在画面内，停 5 秒。**标记 M2-2**。
4. 停在 yz-062 那一行（带 ⚠️），停 4 秒。**标记 M2-3**。
5. 结束录制。

### S3 看本周待拆（原始片段 `1-2-S3.mp4`）

1. 开始录制。点击 `本周待拆.md` 文件卡片。
2. 停在“最值得拆”的结论部分 5 秒。**标记 M3-1**。
3. 滚到“待核对”部分（如有），停 3 秒。**标记 M3-2**（没有就跳过）。
4. 结束录制。

**此时按“C. 分支”判断是否录 S4。**

### S4 纠正待拆清单（仅主线，原始片段 `1-2-S4.mp4`）

1. 开始录制，回到 S1 的任务。点击输入框，粘贴（原样）：

```text
请复核 成果/1-2/本周待拆.md：yz-062 播放 88,000，但点赞只有 60、评论 8，互动率约 0.08%，低于雷达 0.15% 的提醒线，周报里带 ⚠️。这条要先核对数据（可能是投流或录入错误），不能列为“最值得拆”，请移到“待核对”。
本周待拆改为两条：jz-091（学画面做法，留给 ⑤ 视频复刻）和 gj-118（学内容套路，留给 ④ 爆款复刻），各写一句为什么适合阿夏。
再逐条对照 成果/1-2/雷达周报.md，确认解读里引用的倍数、播放量和周报完全一致。更新 本周待拆.md。
```

2. 停 3 秒。**标记 M4-1**。
3. 发送，等待完成。
4. 打开更新后的 `本周待拆.md`，停在两条待拆和“待核对”部分 5 秒。**标记 M4-2**。
5. 结束录制。

## C. 分支

S3 结束后检查：

```sh
F="$WS/成果/1-2/本周待拆.md"
grep -n -E "yz-062|香水" "$F"
grep -n -E "jz-091|gj-118" "$F"
grep -n -E "[0-9]+(\.[0-9])?x" "$F"   # 列出引用的倍数，和周报逐个对照
grep -n -E "[0-9]+(\.[0-9])?x" "$WS/成果/1-2/雷达周报.md"
```

打开文件确认 yz-062 出现在哪个标题下。

- **主线**（录 S4）：满足任一条——yz-062 被列为“最值得拆”（或排在待拆第一）；待拆里没有同时包含 jz-091 和 gj-118；解读里引用的倍数或播放量与周报不一致（例如把 25.1x 写成 25x、26.6x 写成 27x）。
- **分支 B**（跳过 S4）：yz-062 在“待核对”，待拆为 jz-091 和 gj-118，且引用的数字与周报一致。剪辑表镜头 8–9 换成分支 B 镜头。
- 周报里的倍数和“预期结果”不一致：说明练习数据被改动过，停止录制，检查 `$WS/资料/对标快照-2026-10-31/` 是否与仓库一致，写进 report.md。
