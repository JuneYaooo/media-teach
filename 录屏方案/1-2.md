# 1-2 对标爆款雷达：找出对标这周爆了的那条 — 录制规格

## 基本信息

| 项目 | 内容 |
| --- | --- |
| 输出文件 | `自媒体教程/录屏/1-2-WorkBuddy实操.mp4`（及同名 .json、.vtt） |
| 目标时长 | 3 分 45 秒 – 4 分 45 秒（安装和整理数据的等待已加速） |
| 前置产物 | `$WS/成果/1-1/` 里的对标清单；`录屏方案/_work/1-1/report.md` 里“选定对标”的 3 个账号名（benchmark-outlier-radar 本课 S0 现场安装，01 不装） |
| 用到的素材 | 无文件。数据由 Agent 读取 1-1 选定对标的抖音公开主页整理 |
| 这一段要教会 | ① 雷达原理：同账号同格式、发布日相邻 15 条的中位数作基线，倍数 = 单条 ÷ 基线，分档和置信度；② 抖音看不到别人的播放量，所以用互动倍数；③ 数据要先整理好交给它，它不爬数据；④ 怎么核对：数据抽查、数字没改、置信度、25 倍以上先查基线、原因是假设；⑤ 第一次用雷达先装：用讲义的安装提示词让 WorkBuddy 装，到“已安装”确认开关开着 |

**本段使用真实抖音账号的公开数据。** 画面只展示账号名和公开数字，不对头像、作品画面做特写；旁白不评价任何真实账号。不演示 MediaCrawler 或任何批量采集。

## 预期结果

结果随录制日期变化，没有固定答案。合格的产物：

- 一张数据表：3 个账号各约 20 条作品，有标题、发布日期、点赞、评论、收藏、转发；看不到的为空。
- 一份周报：用互动倍数；有基准日、指标说明、异常条目（倍数、档位、置信度）；没算倍数的行有说明。
- 解读和“本周最值得拆”：原因写成假设，引用的数字与周报一致。

如果 3 个账号里没有任何 ≥2x 的条目：照实录，旁白按镜头 7B 处理。

## B. 录制步骤

产物文件名以 Agent 实际生成为准，下文用的是示意名。

### S0 安装技能（原始片段 `1-2-S0.mp4`）

讲义“你要准备什么”里的安装提示词，原样演示一遍。安装等待在剪辑时加速。

1. 开始录制。点“新建任务”，确认工作空间为 `阿夏的AI片场`。
2. 点击输入框，粘贴（原样）：

```text
帮我安装 benchmark-outlier-radar 技能：https://github.com/JuneYaooo/benchmark-outlier-radar。装之前先告诉我它要装哪些东西、会不会联网或花钱，我确认后再装。需要 Key 时停下来，告诉我写到哪，我自己填，不要在对话里显示。
```

3. 停 2 秒。**标记 M0-1**。发送。它列出要装的东西、会不会联网或花钱、等你确认时 **标记 M0-2**，停 2 秒。然后粘贴并发送：

```text
确认，装吧。
```

4. 等待安装（不动鼠标）。请求执行命令时点“允许”。出现“安装完成”一类说明时 **标记 M0-3**。
5. 左侧栏点“专家·技能·连接器”→“技能”→“已安装”，找到 `benchmark-outlier-radar`，鼠标停在开关旁 2 秒。**标记 M0-4**。看不到时：暂停录制，镜头外重启 WorkBuddy，恢复录制后补拍这一步。
6. 结束录制。

> 安装中途它停下来要 Key、要装缺的运行环境、或说已经装过：照实录下，按讲义回复（同意装运行环境；Key 在镜头外填），写进 report.md。

### S1 整理对标数据（原始片段 `1-2-S1.mp4`）

1. 开始录制。点“新建任务”，确认工作空间为 `阿夏的AI片场`。
2. 点击输入框，粘贴（把 `<1-1 选定的对标>` 换成 report.md 里的 3 个账号名，用顿号隔开，其余原样）：

```text
打开 <1-1 选定的对标> 这几个账号的主页，把每个账号最近 20 条作品整理成一张表：标题、发布日期、点赞、评论、收藏、转发。页面上看不到的数留空，不要填 0，也不要估。整理完先给我看一眼，放到 成果/1-2。
```

3. 停 3 秒。**标记 M1-1**。
4. 发送。它开始打开主页时 **标记 M1-2**。
5. 等待完成（不动鼠标）。出现数据表文件卡片时 **标记 M1-3**。
6. 点开数据表，停 4 秒。**标记 M1-4**。
7. 结束录制。

> 读不出主页时：它应该停下来说明原因。照实录，镜头外按讲义“常见问题”处理（换时间重试，或自己截图作品列表发给它），并写进 report.md。不要改提示词。

### S2 抽查数据（原始片段 `1-2-S2.mp4`）

1. 镜头外在数据表里挑 2 条作品（一条互动高、一条普通）。
2. 切到浏览器。开始录制。打开第一条作品页，画面保持整页，停 3 秒。**标记 M2-1**。
3. 打开第二条作品页，停 3 秒。**标记 M2-2**。
4. 切回 WorkBuddy 数据表，停在这两行 3 秒。**标记 M2-3**。
5. 结束录制。

### S3 跑雷达（原始片段 `1-2-S3.mp4`）

1. 开始录制，回到 S1 的任务。点击输入框，粘贴（原样）：

```text
用 benchmark-outlier-radar 对这几个对标跑一次雷达，以今天为基准，用互动数算倍数，出一份周报。解读时只引用周报里的数字，原因写成假设。最后结合我的账号定位，选出本周最值得拆的一条，说清要学的是内容套路还是画面做法。
```

2. 停 3 秒。**标记 M3-1**。
3. 发送。回复里出现运行雷达脚本的提示时 **标记 M3-2**。确认它用的是互动指标（命令里有 `--metric interactions` 或回复里写明“互动倍数”），没有的话写进 report.md。
4. 等待完成，出现周报文件卡片时 **标记 M3-3**。
5. 结束录制。

### S4 看周报（原始片段 `1-2-S4.mp4`）

1. 开始录制。点开周报，停在开头（基准日、指标说明）3 秒。**标记 M4-1**。
2. 滚到异常条目表，停 5 秒（能看到基线、样本、倍数、档位、置信几列）。**标记 M4-2**。
3. 滚到解读和“本周最值得拆”，停 5 秒。**标记 M4-3**。
4. 结束录制。

### S5 纠正（仅主线，原始片段 `1-2-S5.mp4`）

1. 开始录制，回到同一任务。按 C 节模板写一句纠正，粘贴，停 3 秒。**标记 M5-1**。
2. 发送，等待完成。打开更新后的文件，停在改动处 5 秒。**标记 M5-2**。
3. 结束录制。

## C. 分支

S4 后检查：

```sh
ls "$WS/成果/1-2/"
F=$(ls -t "$WS/成果/1-2/"*.md | head -1)
grep -n -E "interactions|互动" "$F" | head -3
grep -n -E "25x|🔥 25" "$F" | head
```

再对照周报表格读一遍解读部分。

- **主线（录 S5）**：满足任一条：
  - S2 抽查发现数据表里的数字和作品页不一致，或者看不到的数被填了 0；
  - 解读里引用的倍数或互动数在周报表格里找不到（被四舍五入或记错）；
  - 选为“最值得拆”的条目置信度为“低”，或者只是 2–5 倍的观察档；
  - 有 25 倍以上的条目，解读没提“先核对基线”就直接当爆款。

  纠正模板（按实际问题选一句，填实际值）：
  - “<作品标题> 的点赞你写的是 <A>，作品页上是 <B>，请回主页重新核对这个账号的数据，看不到的留空，再重跑雷达。”
  - “解读里说 <作品> 是 <X> 倍，周报里是 <Y> 倍，请按周报原数改，其他引用也逐条对一遍。”
  - “<作品> 置信度是低，基线样本太少，别选它当本周待拆，换一条置信度中以上的。”
  - “<作品> 超过 25 倍，先看看这个账号的基线是不是被几条特别低的作品拉低了，写清楚再决定要不要拆。”
- **分支 B（跳过 S5）**：以上都没出现。剪辑表镜头 11–12 换成 11B–12B。
- **没有任何 ≥2x 条目**：照实录，镜头 7 换成 7B，“本周最值得拆”按它的说明讲；report.md 注明，3-1、3-2 照常用自制样片演示，不受影响。

**数字以实际为准**：旁白中 `〔〕` 里的内容按实际结果填写，写进 report.md。
